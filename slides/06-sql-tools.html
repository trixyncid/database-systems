Bagian 1 / 3

Kenalan dulu

SQL itu bahasa. Sebelum bicara, kita perlu tahu siapa yang diajak bicara dan lewat jendela apa.

Apa itu SQL?

Bahasa untuk “berbicara” dengan database.

SQL (Structured Query Language) dibaca hampir seperti kalimat bahasa Inggris. Kamu menulis apa yang kamu mau; database yang memikirkan cara mengambilnya.

SELECT nama, kota
FROM pelanggan;
→

“Ambilkan nama dan kota dari tabel pelanggan.”

SQL dipakai hampir semua database relasional: MySQL, MariaDB, PostgreSQL, SQL Server, Oracle. Perintah dasarnya sama, jadi yang kamu pelajari hari ini berlaku di mana-mana.

Dua bagian yang perlu ada

Server menyimpan datanya. Aplikasi adalah jendela untuk mengetik perintah.

Kamu

Menulis perintah SQL

Mengetik SELECT, INSERT, dan seterusnya.

Aplikasi

MySQL Workbench atau phpMyAdmin

Tempat mengetik perintah, mengirimnya ke server, dan melihat hasilnya dalam bentuk tabel.

Server

MySQL atau MariaDB

“Mesin” yang benar-benar menyimpan data dan menjalankan perintah. Harus dinyalakan dulu.

Ibarat restoran: server adalah dapurnya, aplikasi adalah pelayan yang mencatat pesanan, dan SQL adalah bahasa yang dipakai untuk memesan.

Aturan menulis SQL

Lima kebiasaan kecil yang mencegah banyak error.

  1. Akhiri setiap perintah dengan titik koma ;

  2. Nama tabel dan kolom: huruf kecil, tanpa spasi. Nama Pelanggan menjadi nama_pelanggan.

  3. Teks dan tanggal pakai kutip tunggal: 'Medan', '2026-10-02'.

  4. Tanggal selalu tahun-bulan-tanggal: '2026-10-02', bukan '02-10-2026'.

  5. Kata kunci boleh huruf kecil, tapi menulisnya KAPITAL membuat perintah lebih mudah dibaca.

Jebakan khas Indonesia

Angka ditulis tanpa titik ribuan.

-- maksudnya tiga puluh ribu
INSERT INTO produk VALUES ('P05', 'Keripik', 30.000);

MySQL membaca titik sebagai tanda desimal, jadi yang tersimpan 30, bukan 30000. Dan tidak ada pesan error. Tulis 30000.

Bagian 2 / 3

Membuat wadahnya

Kita mulai dari hasil normalisasi Toko Kak Rina di pertemuan 05: empat tabel dalam bentuk 3NF.

Dari rancangan ke SQL

Setiap tabel hasil normalisasi menjadi satu CREATE TABLE.

Hasil 3NF pertemuan 05

  • Pelanggan (Kode Plg, Nama, No HP, Kota)
  • Produk (Kode Produk, Nama Produk, Harga)
  • Pesanan (No Pesanan, Tanggal, Kode Plg)
  • Detail Pesanan (No Pesanan, Kode Produk, Jumlah, Harga Jual)

Nama di database

  • pelanggan (kode_plg, nama, no_hp, kota)
  • produk (kode_produk, nama_produk, harga)
  • pesanan (no_pesanan, tanggal, kode_plg)
  • detail_pesanan (no_pesanan, kode_produk, jumlah, harga_jual)

Harga Jual adalah harga saat transaksi, dari “catatan bisnis” di pertemuan 05. Nanti di latihan kamu akan lihat gunanya.

Langkah 1 · CREATE DATABASE

Buat databasenya, lalu “masuk” ke dalamnya.

CREATE DATABASE toko_kak_rina;
USE toko_kak_rina;

CREATE DATABASE membuat “lemari” kosong bernama toko_kak_rina.

USE memberi tahu server: perintah selanjutnya ditujukan ke lemari ini.

Error 1046No database selected

Muncul kalau kamu lupa USE. Di Workbench, kamu juga bisa klik dua kali nama database di panel Schemas sampai tulisannya tebal.

Langkah 2 · Tipe data

Setiap kolom harus punya tipe: isinya angka, teks, atau tanggal?

TipeUntuk apaContoh di Toko Kak Rina
INTBilangan bulat yang bisa dihitung.jumlah 2, harga rupiah 85000
DECIMAL(10,2)Angka desimal yang harus tepat.berat 1.25 kg, harga dalam dolar
VARCHAR(n)Teks, paling panjang n huruf.nama, kota, kode 'C01', no HP
DATETanggal, format tahun-bulan-tanggal.tanggal pesanan '2026-10-02'

Kenapa No HP pakai VARCHAR, bukan INT? Angka nol di depan (0812) akan hilang, ada tanda strip, dan nomor HP tidak pernah dijumlahkan. Aturannya: kalau tidak akan dihitung, simpan sebagai teks.

Langkah 3 · CREATE TABLE

Tabel pertama: pelanggan.

CREATE TABLE pelanggan (
  kode_plg  VARCHAR(5)   PRIMARY KEY,
  nama      VARCHAR(100) NOT NULL,
  no_hp     VARCHAR(15),
  kota      VARCHAR(50)
);

  1. Nama tabel, lalu daftar kolom di dalam kurung. Setiap kolom dipisah koma.

  2. PRIMARY KEY: kunci utama. Wajib unik dan tidak boleh kosong.

  3. NOT NULL: kolom wajib diisi. Pelanggan tanpa nama akan ditolak.

  4. Kolom tanpa NOT NULL boleh kosong. Pelanggan boleh belum mengisi kota.

Perhatikan: kolom terakhir (kota) tidak diakhiri koma. Koma berlebih sebelum tanda kurung tutup adalah error yang paling sering muncul.

Langkah 4 · FOREIGN KEY

Garis di ERD menjadi FOREIGN KEY ... REFERENCES.

CREATE TABLE produk (
  kode_produk  VARCHAR(5)   PRIMARY KEY,
  nama_produk  VARCHAR(100) NOT NULL,
  harga        INT          NOT NULL
);

CREATE TABLE pesanan (
  no_pesanan  VARCHAR(10) PRIMARY KEY,
  tanggal     DATE        NOT NULL,
  kode_plg    VARCHAR(5)  NOT NULL,
  FOREIGN KEY (kode_plg)
    REFERENCES pelanggan (kode_plg)
);

“Kolom kode_plg di tabel pesanan harus menunjuk ke kode_plg yang ada di tabel pelanggan.”

Dengan aturan ini, database sendiri yang menjaga datanya. Pesanan dari pelanggan yang tidak terdaftar akan ditolak, bukan dibiarkan masuk.

Tipe data kolom FK harus sama dengan kolom yang ditunjuk: di sini sama-sama VARCHAR(5).

Langkah 5 · Kunci gabungan

Tabel jembatan: dua kolom bersama-sama menjadi kunci.

CREATE TABLE detail_pesanan (
  no_pesanan   VARCHAR(10),
  kode_produk  VARCHAR(5),
  jumlah       INT NOT NULL,
  harga_jual   INT NOT NULL,
  PRIMARY KEY (no_pesanan, kode_produk),
  FOREIGN KEY (no_pesanan)
    REFERENCES pesanan (no_pesanan),
  FOREIGN KEY (kode_produk)
    REFERENCES produk (kode_produk)
);

  1. Kalau kuncinya lebih dari satu kolom, tulis PRIMARY KEY (kolom1, kolom2) sebagai baris tersendiri di akhir.

  2. Kedua kolom itu sekaligus FK: satu ke pesanan, satu ke produk. Persis seperti tanda PK · FK di pertemuan 05.

  3. Pasangan yang sama (misalnya INV-001 + P01) tidak bisa dimasukkan dua kali.

Urutan itu penting

Buat tabel induk dulu, baru tabel anak.

pelangganproduk → pesanan → detail_pesanan

Tabel pesanan menunjuk ke pelanggan. Kalau pelanggan belum dibuat, server tidak tahu harus menunjuk ke mana.

Error 1824Failed to open the referenced table 'pelanggan'

Artinya: “tabel yang kamu tunjuk dengan REFERENCES belum ada.” Buat tabel induknya dulu, lalu jalankan ulang.

Bagian 3 / 3

Mengisi & mengubah data

Wadahnya sudah jadi. Sekarang kita isi, baca, ubah, dan hapus. Sekalian kita buktikan bahwa anomali dari pertemuan 05 benar-benar hilang.

Create · INSERT

Memasukkan data: sebutkan kolomnya, lalu nilainya.

INSERT INTO pelanggan (kode_plg, nama, no_hp, kota) VALUES
  ('C01', 'Dewi Anggraini',   '0812-1111', 'Medan'),
  ('C02', 'Rudi Simanjuntak', '0813-2222', 'Binjai'),
  ('C03', 'Sinta Halim',      '0857-3333', 'Siantar');

Urutan nilai = urutan kolom yang kamu tulis di dalam kurung pertama.

Satu INSERT bisa memasukkan banyak baris. Pisahkan setiap baris dengan koma.

Foreign key bekerja

Coba masukkan pesanan dari pelanggan yang tidak ada.

INSERT INTO pesanan (no_pesanan, tanggal, kode_plg)
VALUES ('INV-005', '2026-10-06', 'C99');
Error 1452Cannot add or update a child row: a foreign key constraint fails (`toko_kak_rina`.`pesanan`, … REFERENCES `pelanggan` (`kode_plg`))

Database menolak, karena pelanggan C99 tidak terdaftar.

Di spreadsheet, kesalahan ketik seperti ini akan lolos begitu saja. Di database, aturan FK yang kita tulis tadi langsung menjaganya.

Update · UPDATE

Dewi ganti nomor HP. Ingat anomali ubah?

UPDATE pelanggan
SET    no_hp = '0812-9999'
WHERE  kode_plg = 'C01';
OK1 row(s) affected

SET menentukan kolom dan nilai barunya. WHERE menentukan baris mana yang diubah.

Di sheet lama, nomor Dewi tersebar di banyak baris. Sekarang cukup 1 baris, dan semua pesanan Dewi otomatis ikut benar.

kode_plgnamano_hpkota
C01Dewi Anggraini0812-9999Medan
C02Rudi Simanjuntak0813-2222Binjai
Hati-hati

UPDATE atau DELETE tanpa WHERE mengenai semua baris.

UPDATE pelanggan
SET    kota = 'Medan';

Maksudnya mengubah satu pelanggan, tapi lupa WHERE. Hasilnya: semua pelanggan pindah ke Medan. Tidak ada tombol undo.

Pengaman di Workbench

Error 1175You are using safe update mode and you tried to update a table without a WHERE that uses a KEY column.

Workbench menyalakan Safe Updates sejak awal, jadi perintah seperti ini ditolak. phpMyAdmin tidak punya pengaman ini.

Kebiasaan aman: tulis WHERE lebih dulu sebelum menulis SET. Dan jangan matikan Safe Updates.

Delete · DELETE

Rudi batal pesan. Hapus pesanan INV-002.

Kalau langsung menghapus pesanannya

DELETE FROM pesanan WHERE no_pesanan = 'INV-002';
Error 1451Cannot delete or update a parent row: a foreign key constraint fails (`toko_kak_rina`.`detail_pesanan`, …)

Pesanan ini masih punya baris di detail_pesanan. Database tidak mau meninggalkan detail “yatim”.

Urutan yang benar: anak dulu, baru induk

DELETE FROM detail_pesanan WHERE no_pesanan = 'INV-002';
DELETE FROM pesanan        WHERE no_pesanan = 'INV-002';
OK1 row(s) affected  ·  1 row(s) affected

Kebalikan dari urutan saat membuat tabel.

Ingat anomali hapus?

Pesanan Rudi sudah hilang. Kopi Sidikalang?

Latihan

Giliranmu

Tiga latihan langsung di laptop. Kerjakan berpasangan: satu orang mengetik, satu orang memeriksa, lalu bergantian.

Latihan 1  Mudah

Toko Kak Rina kedatangan produk baru.

Mulai dari database toko_kak_rina yang lengkap (jalankan ulang file toko-kak-rina.sql kalau perlu).

  1. Tambahkan produk baru: P05, Keripik Ubi Pedas, harga 30000.

  2. Sinta (C03) memesan 2 Keripik Ubi Pedas pada 6 Oktober 2026, nomor pesanan INV-005. Masukkan ke tabel pesanan dan detail_pesanan.

  3. Harga Bika Ambon naik menjadi 95000. Ubah di tabel produk.

  4. Jalankan SELECT * FROM detail_pesanan; Apakah harga_jual INV-001 ikut berubah menjadi 95000? Kenapa itu justru benar?

Kunci jawaban · Latihan 1

Pesanan baru = satu baris di pesanan + baris di detail.

INSERT INTO produk (kode_produk, nama_produk, harga)
VALUES ('P05', 'Keripik Ubi Pedas', 30000);

INSERT INTO pesanan (no_pesanan, tanggal, kode_plg)
VALUES ('INV-005', '2026-10-06', 'C03');

INSERT INTO detail_pesanan
  (no_pesanan, kode_produk, jumlah, harga_jual)
VALUES ('INV-005', 'P05', 2, 30000);

UPDATE produk SET harga = 95000
WHERE kode_produk = 'P01';

Urutan penting: produk dan pesanan harus ada dulu sebelum detail_pesanan, karena detail menunjuk ke keduanya.

Nomor 4: tidak berubah, harga_jual INV-001 tetap 85000. Itu benar, karena Dewi memang membayar 85000. Harga di produk adalah harga hari ini; harga di detail_pesanan adalah harga saat transaksi.

Latihan 2  Sedang

Dari kertas ke database: Kelas Kreator.

Ingat Latihan 1 di pertemuan 05? Ubah hasil normalisasinya menjadi database kelas_kreator.

Hasil 3NF

  • Peserta (Kode Peserta, Nama Peserta, No HP)
  • Kelas (Kode Kelas, Nama Kelas, Instruktur, Biaya)
  • Pendaftaran (No Daftar, Tanggal, Kode Peserta)
  • Detail Pendaftaran (No Daftar, Kode Kelas)

Tugas

  1. Buat database dan keempat tabelnya, lengkap dengan PK dan FK.

  2. Isi datanya dari sheet di pertemuan 05 (3 peserta, 3 kelas, 4 pendaftaran).

  3. Cek dengan SHOW TABLES; dan SELECT * di setiap tabel.

Petunjuk: pilih tipe data sendiri. Biaya dihitung, jadi INT. Kode dan No HP tidak dihitung, jadi VARCHAR.

Kunci jawaban · Latihan 2

Induk dulu (peserta, kelas), baru anak.

CREATE DATABASE kelas_kreator;
USE kelas_kreator;

CREATE TABLE peserta (
  kode_peserta  VARCHAR(5)   PRIMARY KEY,
  nama_peserta  VARCHAR(100) NOT NULL,
  no_hp         VARCHAR(15)
);

CREATE TABLE kelas (
  kode_kelas  VARCHAR(5)   PRIMARY KEY,
  nama_kelas  VARCHAR(100) NOT NULL,
  instruktur  VARCHAR(100),
  biaya       INT          NOT NULL
);

CREATE TABLE pendaftaran (
  no_daftar     VARCHAR(10) PRIMARY KEY,
  tanggal       DATE        NOT NULL,
  kode_peserta  VARCHAR(5)  NOT NULL,
  FOREIGN KEY (kode_peserta)
    REFERENCES peserta (kode_peserta)
);
CREATE TABLE detail_pendaftaran (
  no_daftar   VARCHAR(10),
  kode_kelas  VARCHAR(5),
  PRIMARY KEY (no_daftar, kode_kelas),
  FOREIGN KEY (no_daftar)
    REFERENCES pendaftaran (no_daftar),
  FOREIGN KEY (kode_kelas)
    REFERENCES kelas (kode_kelas)
);
